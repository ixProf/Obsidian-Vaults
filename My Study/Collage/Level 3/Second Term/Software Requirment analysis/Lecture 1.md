
# 1. What is Software?

Software is **not just code**. It is a complete system that consists of:

1. **Programs (code)**
    
2. **Documentation** (manuals, guides, system descriptions)
    

So:  
**Software = Code + Documentation**

### Additional Notes:

- Documentation is essential for:
    
    - Understanding the system
    - Supporting users
    - Maintaining and updating the software
- Without documentation, software becomes difficult to maintain and reuse

---

# 2. Software Types (Markets)

### 1. Custom Software

- Built for a **specific client**
    
- Tailored to exact requirements
    
- Usually more expensive
    
- Hard to reuse
    

Example: Company management system

### 2. Generic Software

- Built for **general users**
    
- Designed for a wide market
    
- Cheaper per user
    
- Easier to distribute
    

Example: Microsoft Word, browsers

### Additional Insight:

- Many real-world systems combine both types
    

---

# 3. What is Software Engineering?

> Software engineering is an **==engineering discipline== concerned with all aspects of software production**

### Additional Notes:

- It follows structured methods, processes, and standards
    
- It is not just coding
    

### Main Goal:

Build software that is:

- On time
    
- Within budget
    
- High quality
    

### It includes:

- Analysis
    
- Design
    
- Development
    
- Testing
    
- Maintenance
    

---

# 4. Core Software Engineering Processes

### 1. Software Specification

- Define system functionality
    
- Define constraints
    

### 2. Software Development

- Design + Implementation
    

### 3. Software Validation

- Ensure system meets customer requirements
    

### 4. Software Evolution

- Modify and update the system over time

These processes are **iterative**, not strictly sequential

# 5. Key Challenges in Software Engineering

### 1. Increasing Diversity

- Different platforms (mobile, web, embedded systems)
    
- Different environments and users
    

### 2. Faster Delivery

- High demand for rapid development
    
- Led to Agile methodologies
    

### 3. Trustworthy Software

- Must be:
    
    - Secure
        
    - Reliable
        
    - Safe
        

Especially important in:

- Medical systems
    
- Banking systems
    
- Safety-critical systems
    

---

# 6. Cost Distribution

- **60% → Development**
    
- **40% → Testing**
    

### Important Insight:

- Testing is expensive because:
    
    - Bugs found late are more costly
        
    - Failures in production can be critical
        

Rule:

> The later a bug is found, the more expensive it is

---

# 7. Is There a Best Method?

**No single best method**

### The approach depends on:

- Organization
    
- People
    
- Type of software (most important)
    

### Example:

- Safety-critical systems → structured models (e.g., Waterfall)
    
- Startups → Agile
    

---

# 8. Attributes of Good Software

### 1. Maintainability

- Easy to update and modify
    
- Most important in long-term systems
    

### 2. Dependability & Security

Includes:

- Reliability
    
- Safety
    
- Security
    

### 3. Efficiency

- Good performance
    
- Efficient use of:
    
    - CPU
        
    - Memory
        
    - Time
        

### 4. Acceptability

- Usable and understandable
    
- Compatible with other systems
    
- Good user experience
    

---

# 9. Factors Affecting Development

- Organization (company structure and policies)
    
- People (team skills and experience)
    
- Software type (main factor)
    

### Important:

Software type determines:

- Architecture
    
- Tools
    
- Testing level
    

---

# 10. Types of Software Applications

### 1. Stand-alone Applications

- Run locally
    
- No internet required
    

Example: calculator

### 2. Transaction-based Systems

- Handle user requests and responses
    
- Often web-based
    

Example: e-commerce systems

### 3. Embedded Systems

- Run inside hardware devices
    
- Often real-time systems
    
- Require high reliability
    

Example: car systems, medical devices

### 4. Batch Systems

- Process large amounts of data automatically
    

Example: billing systems

### 5. Entertainment Systems

- Games, media platforms
    

### 6. Simulation Systems

- Model real-world systems
    

Example: flight simulators

### 7. Data Collection Systems

- Collect and analyze data
    

Example: sensor systems

### 8. Systems of Systems

- Multiple independent systems working together
    

Example: smart cities

---

# 11. Web-Based Systems

Modern systems are mostly web-based because:

- Easier updates (centralized)
    
- Lower cost
    
- Easier management
    

### Key Idea:

Update once on the server → affects all users

---

# 12. Web Services & SaaS

### Web Services:

- Reusable components available over the internet
    
- Used to build applications
    

### SaaS (Software as a Service):

- Full applications delivered online
    
- No installation required
    

Example: Google Docs

---

# 13. Software Engineering Ethics

Engineers must follow:

- Confidentiality
    
- Competence
    
- Intellectual property protection
    
- Avoid misuse of systems
    

### Key Idea:

Professional responsibility is as important as technical skills

---

# 14. ACM/IEEE Code of Ethics

Main principles:

1. Public interest
    
2. Client and employer interest
    
3. Product quality
    
4. Professional judgment
    
5. Ethical management
    
6. Professional reputation
    
7. Respect for colleagues
    
8. Lifelong learning

# 15. Case Study: Insulin Pump System

A **safety-critical embedded system**

### Function:

- Monitor blood sugar
    
- Compute insulin dose
    
- Deliver insulin automatically
    

---

# Risks

### Low Blood Sugar (Hypoglycemia)

- Brain damage
    
- Coma
    
- Death
    

### High Blood Sugar (Hyperglycemia)

- Long-term damage
    
- Eyes and kidneys affected
    

---

# 16. Core Requirements

- Availability (24/7 operation)
    
- Accuracy (correct insulin calculation)
    
- Data logging
    
- Fail-safe operation
    

---

# 17. Additional Requirements

### Safety:

- Self-diagnosis
    
- Alarm system
    
- Redundancy (backup components)
    

### Usability:

- Simple user interface
- Clear alerts

### Data:

- Export data
    
- Share with healthcare providers
