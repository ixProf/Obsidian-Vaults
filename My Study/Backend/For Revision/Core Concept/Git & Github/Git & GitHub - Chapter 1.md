# Chapter 1: What is Git

## اي هو ال Version Control System ؟

هو برنامج بنستخدمه علشان نتابع التعديلات الي احنا بنعملها على الفايل والفايلات الي احنا بنعدل عليها على مدار الوقت علشان يكون معانا نسخ من الملفات علشان لو حصل اي مشكلة نقدر نسترجع النسخة القديمة في اي وقت.

### النوع التقليدي: Local Version Control Sys


![[Pasted image 20260903025843.png]]

هنا دا بديل للطريقة التقليدية الي كانت مستخدمة في التعديل على الملفات، بدل ما كنت مثلا كل ملف تعمله فولدر جديد واسم جديد يعبر عن الفيرجن انه جديد، هنا بقى الوضع مختلف

بس الحاجه دي للأسف معرضة جدا للخطأ ولا يعتمد عليها في عدد الفايلات الكتير
وكمان ليه حدود <mark style="background: #FFF3A3A6;">انه مش بيسمحلنا نشتغل مع ناس تانية</mark>، وهنا تيجي فكرة Centralized and Distributed VCS

### Centralized Version Control System (CVCS)

فكرته انك لو عايز تشتغل مع حد فأرفع شغلك اونلاين، على الإنترنت يعني، لو عايز تشغل VCS مع ناس تانية بسيطة حطه على سيرفر، وفيه بتخزن التعديلات الي انت عملتها

المكان الي بيتخزن فيه التعديلات اسمه ==Repository== 
بس الحاجه دي كان فيها مشاكل بعض الشئ:
- السيرفر دا لو حصله اي حاجه فكل حاجه عليه هتروح، ومش هنقدر نسجل عليه أي تعديلات ممكن تحصل
- بطئ ودا بسبب سرعة الإنترنت
- مش هتقدر تشتغل اوفلاين
![[Pasted image 20260903031815.png]]

وعلشان كدا جه الحل:

### Distributed Version Control System DVCS

وهنا حللك كل المشاكل الي في ال Centralized ساعتها بقى كل واحد عنده نسخة من التعديلات ف الهيستوري الي كان في السيرفر، بقى موجود كمان مع اليوزرز 
![[Pasted image 20260903032139.png]]

والبطئ برضو اتحل فدلوقتي بأن عندك كل حاجه بقت لوكال، ف انت بتسجل التعديلات عندك على اللوكال ولو حابب تشير التعديلات دي ممكن تشيرها عن طريق السيرفر بشكل طبيعي

فدلوقتي السيستم بقى عبارة عن حاجه لمشاركة التعديلات، بعد ما كان حاجه <mark style="background-color: #FFF3A3A6;"> (يتمحور) </mark> عليها ال VCS بقى عبارة عن حاجه هامشية لمشاركة التعديلات
ودا الي بقى عليه ال Git انه عبارة عن ==Distributed Version Control System==

![[Pasted image 20260903033307.png]]

### مرحلة الـConfigruation

دي مرحلة علشان تعرفه يعني انت مين وكدا بتستخدم فيها امر اسمه
```bash
git config --global user.name #yourname
git config --global user.email #youremail
```

انت عندك 3 مراحل في الـConfiguration
- `--local`: ودا عبارة عن انه يكون خاص ببروجيكت معين بس
- `--global`: خاص بكل بروجيكتات اليوزر
- `--system` دا خاص للبروجيكتات الي شغال عليها كل اليوزرز 

### Start Using Git

علشان تبدأ تستخدم Git في مشروعك هتبدأ تكتب الامر دا في الفولدر بتاع المشروع 
```bash
git init #Initialize git in our project
git init my-project #init specific project
```

لما تعمل git init ف انت كدا بتعمل .git ودي Repository 
وعلشان تشوف الي فايلز الي في المشروع بتاعك وليكن مشروع فاضي وعملتله init هتلاقي عندك .git

### How Dose Git Work?

كيف Git بيشتغل ؟
هو عبارة عن Content-addressable file system يعني اي حاجه انت هتحاول تخزنها في الRepository بتاعه هيديلك Unique Key تقدر تستخدمه علشان تجيب الحاجة الي انت خزنتها

وهنا Git بيتكون من حاجتين:
- الـDatabase: علشان تخزن فيها التعديلات
- الــReferences: علشان تخزن ال Keys الي هو عاملها
![[Pasted image 20260903042524.png]]
علشان توصل للحاجة بسرعة ف فكرة ال id الي بيديهولك بيبقى معتمد على انه يسميه على حاجه موجودة في اسم الكونتنت مثلا لو موجود كلمة hi فتقدر تجيبه من ايدي موجود فيه hi
والحاجة دي اتعملت في حاجه اسمها <mark style="background: #BBFABBA6;">SHA1</mark> ف احنا هنا بنعمل Hashing 
- وهي اني بحول الداتا بتاعتي اي كان عددها او نوعها لنوع معين من الحروف وفي حالة ال <mark style="background: #FF5582A6;">SHA1 بيكونوا 40 حرف.</mark> هيكثاديسيمال بيبدا من 0 ل F (دا بالنسبة لإسم الاوبجيكت)
- بنشيل في الاوبجيكت 3 حاجات (النوع والحجم والداتا) وبنفصل بين 3 عن طريق empty-byte علشان git كان شغال بال c ودي واحدة من الطرق الي بتفصل ما بين الداتا، وعلشان نحافظ على المساحة بتاعتنا هنضغط ال Objects علشان نحطها في الداتا بيز عن طريق zlib

فالحالة دي احنا محتاجين نحط ال blobs الي عملناها في حاجه اسمها index او ال Staging Area، ليه ممكن نعمل حاجه زي كدا ؟

علشان احنا محتاجين نتابع التعديلات الي احنا عملناها بشكل واضح، فعلشان تعرف اي التعديلات الي اتعدلت ف انت اكيد محتاج ليها صورة، فتشوف شكلها قبل وبعد ساعتها تعرف اي الي اتغير بالظبط، فنقدر نقول إن عبارة عن فريم صورة.
- اي حاجه جوا الكادر، فدي الحاجة الي انا هصورها
- اي حاجه برا الكادر دا، فدي الحاجة الي مش هقدر اصورها فمش هعرف شكلها عامل ازاي ولا اي الي اتغير فيها

> كل ما يكون في تفاصيل في الصورة كل ما كانت احسن

ف ال index هنا بيضيفلك تفاصيل لصورة الفايل دا زي
- اتعمل امتى
- اتعدل امتى
- البيرمشن بتاعته
- صاحب الفايل دا
- حجمه
- ال blob
- الاسم او الباث بتاعه

علشان تعمل Update لل Index هتحتاج 3 حاجات
- ال Permission 
- ال blob sha1
- ال name / path

فلو هنعمل الفايل بتاعنا الي لسه عاملينه 
```bash

```

نحلل الامر دا :
- هنا انا عملت update-index وطلبت اني اضيف حاجه لل index الي هو `add--`
- علشان اعرف او ادي البيرمشن بتاعته ف انا بدي حاجه اسمها `cacheinfo--` وفي حالتنا دي هو عبارة عن فايل عادي والفايل العادي الكود بتاعه في جيت هو 100644
- وبعدها هتحط ال id بتاع ال blob و الاسم بتاعه

> Tree

ودا بياخد صورة لمحتويات الفولدرز الي موجودة معايا في البروجيكت فهيكون في Tree رئيسية بيتفرع منها كل الشغل بتاعنا، في الحالة دي مفيش غير Tree واحدة علشان احنا معندناش غير فولدر واحد فلو عندنا فولدرات كتير ف على قد الفولدرات هتكون ال Trees 

الـTree بيخزن ايه ؟
- الـfile mode وهو ال Permission
- الـfile name 
- الـfile data وهو ال blob

> ال Permission في Git:
> لو الملف عادي وطبيعي هيكون 100644
> لو الملف executable تقدر تعمله execute فهيكون 100755
> لو الملف عبارة عن shortcut او symbolic فدا هيكون 120000
> لو عبارة عن فولدر فدا هيكون 40000

فعلشان تكتب ال Tree فهتعمل كدا
```bash
git write-tree
```

عندك Git شغالة بحاجه اسمها Three-tree Model
- الـWorking Directory: دا المكان الي انا بخلص فيه شغلي
	- حالة الملف بشكل طبيعي هتبقى: Untracked
	- لو عدلت في الملف ولسه مطلعتهوش لل stage فكدا حالته هتبقى: Modified and Not Staged 
	- عملتله staged او يعني عملتله git add فكدا اصبحت حالة الملف 
		- Modified and Staged
- الـStaging Area او ال Index: ودا المكان الي بحط فيه الحاجة الي المفروض تتسيف
- الـHEAD: دا المكان الي بتتحط فيه الحاجات الي اتسيفت
