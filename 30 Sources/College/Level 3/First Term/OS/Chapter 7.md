This lecture from the Operating Systems course (CS321) at Assiut University , taught by Prof. Khaled F. Hussain , focuses on **Memory Management**, specifically Main Memory.

---

### 1. Memory Protection and Address Space

- The logical address space is defined using a **base register** and a **limit register**.
    
- The **base register** holds the smallest legal physical memory address.
    
- The **limit register** specifies the size of the range.
    
- The hardware protects the memory by ensuring every address generated by the CPU is $\ge$ the base and $<$ (base + limit).
    
- Any violation results in a trap to the operating system.
    

### 2. Address Binding

Address binding is the process of mapping program instructions and data to actual memory addresses. It can happen at three stages:

- **Compile time**: Generates **absolute code** if the memory location is known at the start.
    
- **Load time**: Generates **relocatable code** if the location isn't known until the program is loaded.
    
- **Execution time**: Binding is delayed until run time if the process can move during execution. This requires special hardware and is used by most modern OSs.
    

### 3. Logical vs. Physical Address Space

- A **logical address** is generated by the CPU.
    
- A **physical address** is the address actually seen by the memory unit.
    
- The **Memory-Management Unit (MMU)** is the hardware device that maps virtual/logical addresses to physical addresses at run-time.
    
- In a simple scheme, a **relocation register** (base) is added to every logical address.
    

### 4. Dynamic Loading and Linking

- **Dynamic Loading**: A routine is not loaded into memory until it is called. This allows for better memory-space utilization.
    
- **Dynamic Linking**: Linking is postponed until execution time. A small piece of code called a **stub** is used to locate or load the library routine.
    

### 5. Contiguous Memory Allocation

Each process is contained in a single contiguous section of memory.

- **Memory Allocation**: One method is dividing memory into fixed-sized partitions.
    
- **Dynamic Storage-Allocation Problem**: Strategies to satisfy a request of size $n$ from a list of free holes:
    
    - **First fit**: Allocate the first hole that is big enough.
        
    - **Best fit**: Allocate the smallest hole that is big enough (requires searching the whole list).
        
    - **Worst fit**: Allocate the largest hole.
        

### 6. Fragmentation

- **External Fragmentation**: Total memory exists to satisfy a request, but it is not contiguous. **Compaction** is a solution to shuffle memory contents to place free memory together.
    
- **Internal Fragmentation**: Unused memory that is internal to a partition because the allocated block is slightly larger than requested.
    

---

### 7. Segmentation

Segmentation supports the programmer's view of a program as a collection of logical segments (e.g., main program, stack, subroutines).

- A logical address is a pair: **<segment-number, offset>**.
    
- The **segment table** maps these to physical addresses using a **base** (starting address) and a **limit** (length).
    

### 8. Paging

Paging is the most common memory management scheme as it avoids external fragmentation.

- **Basic Method**: Physical memory is broken into fixed-sized blocks called **frames**, and logical memory is broken into same-sized blocks called **pages**.
    
- **Page Table**: Used to translate the page number ($p$) to a frame number ($f$), which is then combined with the offset ($d$) to find the physical address.
    
- **TLB (Translation Look-aside Buffer)**: A fast hardware cache used to speed up page table lookups. It reduces the need for two memory accesses (one for the table, one for the data).
    
- **Effective Access Time (EAT)**: Calculated by weighting the hit and miss probabilities of the TLB.
    
- **Shared Pages**: Reentrant (non-self-modifying) code can be shared among multiple processes in a paging environment.
    

### 9. Page Table Structures

For large address spaces, the page table itself must be managed:

- **Hierarchical Paging**: Breaking the page table into multiple levels (e.g., Two-level paging).
    
- **Hashed Page Tables**: Common for addresses $> 32$ bits; uses a hash of the virtual page number.
    
- **Inverted Page Tables**: Has one entry for each real page of physical memory, saving space but increasing search time.

This section explains the problem-solving parts of the lecture, including the mathematical rules, logic, and practical examples for memory management.

### 1. Hardware Address Protection (Base and Limit)

Protection is ensured by defining a logical address space using two registers: **Base** and **Limit**.

- **The Rule:** A physical address is valid if it is greater than or equal to the **Base** and less than **Base + Limit**.
    
- **Formula:** $Base \le \text{Target Address} < Base + Limit$.
    
- **Example:** If the **Base** is $300040$ and the **Limit** is $120900$:
    
    - The smallest legal address is **300040**.
        
    - The largest legal address is $300040 + 120900 = \mathbf{420940}$.
        
    - Any address outside this range (e.g., $430000$) results in a trap/addressing error.
        

### 2. Logical to Physical Address Mapping (Relocation)

The Memory-Management Unit (MMU) handles the run-time mapping from logical to physical addresses.

- **The Rule:** The value in the **Relocation Register** is added to every logical address generated by a user process at the time it is sent to memory.
    
- **Formula:** $\text{Physical Address} = \text{Logical Address} + \text{Relocation Register}$.
    
- **Example:**
    
    - **Logical Address:** $346$.
        
    - **Relocation Register:** $14000$.
        
    - **Physical Address:** $346 + 14000 = \mathbf{14346}$.
        

### 3. Dynamic Storage Allocation Strategies

When a process needs $n$ bytes, the OS chooses a "hole" from the list of available free memory.

- **First-fit:** Allocate the **first** hole that is big enough.
    
- **Best-fit:** Allocate the **smallest** hole that is big enough. It produces the smallest leftover hole.
    
- **Worst-fit:** Allocate the **largest** hole. It produces the largest leftover hole.
    
- **Example:** Given holes of sizes $100$ KB, $500$ KB, and $200$ KB:
    
    - To allocate **150 KB**:
        
        - **First-fit** would pick the $500$ KB hole.
            
        - **Best-fit** would pick the $200$ KB hole.
            
        - **Worst-fit** would pick the $500$ KB hole.
            

### 4. Segmentation Addressing

In segmentation, a logical address consists of a two-tuple: **<segment-number, offset>**.

- **The Rule:** The **offset ($d$)** must be between $0$ and the **segment limit**. If valid, it is added to the **segment base** to get the physical address.
    
- **Conditions:**
    
    1. Check: Is $d < \text{Limit}$?.
        
    2. If Yes: $\text{Physical Address} = Base + d$.
        
    3. If No: Trap (addressing error).
        
- **Example:** Using a segment table where Segment 2 has **Limit: 400** and **Base: 4300**:
    
    - For address **<2, 300>**: $300 < 400$ is true. Physical Address = $4300 + 300 = \mathbf{4600}$.
        
    - For address **<2, 500>**: $500 < 400$ is false. Result: **Trap (Error)**.
        

### 5. Paging and Effective Access Time (EAT)

When using a Translation Look-aside Buffer (TLB), performance depends on how often the page is found in the cache (hit ratio).

- **The Rule:** Weight the time for a TLB hit versus a TLB miss by their respective probabilities.
    
- **Formula:** $EAT = (\text{Hit Ratio} \times \text{Time in case of Hit}) + ((1 - \text{Hit Ratio}) \times \text{Time in case of Miss})$.
    
- **Assumptions:** Memory access time = $100$ ns. A "Hit" takes $1$ memory access ($100$ ns). A "Miss" takes $2$ memory accesses ($200$ ns).
    
- **Example (80% Hit Ratio):**
    
    - $EAT = 0.80 \times 100 + 0.20 \times 200 = \mathbf{120 \text{ nanoseconds}}$.
        
- **Example (99% Hit Ratio):**
    
    - $EAT = 0.99 \times 100 + 0.01 \times 200 = \mathbf{101 \text{ nanoseconds}}$.
