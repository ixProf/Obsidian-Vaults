
هذا شرح شامل وتفصيلي لكلاس `FAT` (في ملف `FatTableManager.cs`)، وهو يعتبر **"العقل المدبر"** أو **"خريطة التخزين"** في النظام.

---

### **أولاً: المنطق العام (The Logic)**

كلاس `FAT` (File Allocation Table) هو عبارة عن **جدول** أو **مصفوفة** (Array) تمثل كل "كلاستر" على الديسك.

1. **الفكرة:** الديسك عندك مقسم لـ 1024 قطعة (Cluster). الـ FAT هو جدول فيه 1024 خانة.
    
    - الخانة رقم `x` في الجدول تحكي لنا حالة الكلاستر رقم `x` على الديسك.
        
2. **لغة الإشارة (القيم داخل الجدول):**
    
    - **`0`**: الكلاستر ده **فاضي** ومتاح للاستخدام.
        
    - **`-1`**: دي **نهاية الملف** (EOF). يعني الملف خلص هنا.
        
    - **`رقم آخر (مثلاً 10)`**: يعني "بيانات الملف لسه مخلصتش، روح كمل قراءة في كلاستر رقم 10".
        
3. **السلسلة (Linked List):**
    
    - الملفات الكبيرة بتتخزن متقطعة. الـ FAT هو اللي بيربط القطع دي ببعضها.
        
    - مثال: ملف واخد 3 كلاسترات (5, 9, 12).
        
    - الجدول هيكون: `table[5] = 9`, `table[9] = 12`, `table[12] = -1`.

### **ثانياً: شرح المتغيرات والكونستركتور**

```
public class FAT
{
    // دي الخريطة اللي شايلة حالة الـ 1024 كلاستر بتوعنا
    // موجودة في الرامات (RAM) عشان السرعة
    private int[] table = new int[FSConstants.CLUSTER_COUNT]; 

    public FAT() { } // كونستركتور فاضي
}
```

### **ثالثاً: شرح الدوال (Methods) بالتفصيل**

#### **1. التجهيز والحفظ (`Initialize`, `Load`, `Save`)**

**أ. دالة `Initialize` (التهيئة لأول مرة)**

- **وظيفتها:** تنظيف الجدول وحجز أماكن ملفات النظام الأساسية.
    
- **الخطوات:**
    
    1. تخلي الجدول كله أصفار (فاضي).
        
    2. تحجز الكلاستر `0` (للـ Superblock).
        
    3. تحجز الكلاسترات `1, 2, 3, 4` (للـ FAT نفسه عشان يتخزن فيهم).
        
    4. تحجز الكلاستر `5` (للـ Root Directory).
        
    5. كل المحجوز ده بياخد قيمة `-1`.
        

**ب. دالة `Save` (الحفظ من الرامات للديسك)**

- **وظيفتها:** لما تخلص شغل، لازم تكتب المصفوفة دي على الهارد عشان ماتضعش لما الكهرباء تقطع.
    
- **اللوجيك:**
    
    - المصفوفة نوعها `int` (الرقم 4 بايت).
        
    - الكلاستر الواحد 1024 بايت.
        
    - إذن الكلاستر يشيل: $1024 / 4 = 256$ رقم.
        
    - إحنا عندنا 1024 رقم في الجدول، يبقى محتاجين $1024 / 256 = 4$ كلاسترات لتخزين الجدول.
        
- **الكود:** بيلف على الـ 4 كلاسترات المخصصة للـ FAT، ويحول الأرقام لـ Bytes ويكتبهم.
    

**ج. دالة `Load` (التحميل من الديسك للرامات)**

- **وظيفتها:** عكس `Save`. أول ما البرنامج يفتح، بيقرأ الـ 4 كلاسترات دول، ويجمع الأرقام تاني ويحطهم في المصفوفة `table` عشان نعرف حالة الديسك كانت إيه.

#### **3. أهم دوال (إدارة السلاسل)**

**أ. دالة `AllocateChain` (حجز مساحة لملف جديد)**

- **الوظيفة:** أخطر دالة. بتدور على أماكن فاضية وتربطهم ببعض بسلسلة.
    
- **المدخلات:** `count` (عدد الكلاسترات المطلوبة).
    
- **اللوجيك:**
    
    1. بتمشي على الجدول من أول المنطقة المتاحة للداتا (رقم 6).
        
    2. كل ما تلاقي `0` (مكان فاضي):
        
        - لو ده أول واحد، احفظ رقمه (عشان ده بداية الملف).
            
        - لو مش الأول، اربط اللي قبله بده (`table[prev] = current`).
            
        - علم على الحالي بـ `-1` (مبدئياً).
            
    3. تكرر العملية لحد ما الـ `count` يخلص.
        
    4. لو الديسك مليان والـ `count` لسه ماخلصش، بترمي Exception.
        

**ب. دالة `FreeChain` (حذف ملف)**

- **الوظيفة:** تمشي وراء السلسلة وتصفرها.
    
- **المدخلات:** `start` (رقم أول كلاستر).
    
- **اللوجيك:**
    
    - بيقول: "أنا في كلاستر 5، مين اللي بعدي؟ 9. تمام".
        
    - يخلي كلاستر 5 بـ `0` (فاضي).
        
    - يروح لكلاستر 9 ويسأل: "مين اللي بعدي؟".
        
    - وهكذا لحد ما يوصل لـ `-1`.

### **رابعاً: شرح الكود سطراً بسطر (`Code Walkthrough`)**

تعال نمسك الدوال "الدسمة" في الكود:

#### **كود `Initialize`**

C#

```
public void Initialize()
{
    // 1. تصفير الجدول بالكامل
    for (int i = 0; i < table.Length; i++)
        table[i] = 0;

    // 2. حجز الكلاستر 0 (Superblock)
    table[FSConstants.SUPERBLOCK_CLUSTER] = -1;

    // 3. حجز كلاسترات الـ FAT نفسه (من 1 لـ 4)
    for (int i = FSConstants.FAT_START_CLUSTER;
         i < FSConstants.FAT_START_CLUSTER + FSConstants.FAT_CLUSTER_COUNT; i++)
        table[i] = -1;

    // 4. حجز الـ Root Directory (كلاستر 5)
    table[FSConstants.ROOT_DIR_FIRST_CLUSTER] = -1;
}
```

---

#### **كود `AllocateChain` (الربط)**

C#

```
public int AllocateChain(int count)
{
    int first = -1; // لتخزين رأس السلسلة
    int prev = -1;  // لتخزين الكلاستر السابق (عشان نربطه بالحالي)

    // بنبدأ البحث من رقم 6 (لأن من 0 لـ 5 محجوزين للنظام)
    for (int i = FSConstants.DATA_START_CLUSTER;
         i < table.Length && count > 0; i++)
    {
        if (table[i] == 0) // لقينا مكان فاضي!
        {
            if (first == -1) first = i; // لو ده أول واحد، احفظه
            
            if (prev != -1) table[prev] = i; // اربط اللي فات بده (Link)

            prev = i;       // خلي الحالي هو السابق للخطوة الجاية
            table[i] = -1;  // اقفل الحالي مؤقتاً (EOF)
            count--;        // نقص العدد المطلوب
        }
    }

    // لو اللوب خلصت ولسه محتاجين كلاسترات -> الديسك مليان
    if (count > 0)
        throw new Exception("No disk space");

    return first; // رجع رقم أول كلاستر عشان نخزنه في الـ Directory Entry
}
```

---

#### **كود `FreeChain` (التنظيف)**

C#

```
public void FreeChain(int start)
{
    int cur = start;
    while (cur != -1 && cur != 0)
    {
        int next = table[cur]; // 1. احفظ الطريق للي بعده قبل ما تمسح
        table[cur] = 0;        // 2. صفر الكلاستر الحالي (متاح للكتابة)
        cur = next;            // 3. انتقل للي بعده
    }
}
```

### **الخلاصة**

كلاس `FAT` هو **مدير العقارات**:

- عنده 1024 شقة (Clusters).
    
- في دفتره (`table`)، بيكتب قدام رقم كل شقة: "مين ساكن فيها؟" أو "مين الشقة اللي تابعة لنفس المالك بعدها؟".
    
- لما حد يعوز يسكن، بيدورله على شقق فاضية ويربطهم ببعض (`AllocateChain`).
    
- لما حد يمشي، بيفضي الشقق دي ويخليها متاحة (`FreeChain`).
